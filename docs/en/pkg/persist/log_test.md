# pkg/persist/log_test.go

> 📅 Last Updated: 2026/11/13

## Purpose

`pkg/persist/log_test.go` verifies two core behaviors of `LogWatcher`:

1. **Event → text mapping**: whether the log level and message generated by each `scarecrow` event are correct;
2. **Level filtering**: whether events below `minLevel` are silently dropped.

The test uses the package-private constructor `newLogWatcher(handler, metrics, level)` to inject a capturing handler, so no real log file is written.

## Test Fixtures

```go
type captureLogHandler struct {
    mu      sync.Mutex
    records []LogRecord
}

func (h *captureLogHandler) BeforeStart() error { return nil }
func (h *captureLogHandler) HandleRecord(record LogRecord) error { /* 加锁追加 */ }
func (h *captureLogHandler) AfterStop() error { return nil }
func (h *captureLogHandler) snapshot() []LogRecord { /* 加锁拷贝 */ }
```

- It implements `funnel.RecordHandler[LogRecord]` and only records, never writing to disk.
- `sync.Mutex` protects the slice: `HandleRecord` is called in the `Spout` background goroutine while `snapshot` reads in the test goroutine.

## Test Coverage Points

| Test | Capability covered | Key invariant |
|------|----------|-----------|
| `TestLogWatcherTranslatesEvents` | 9 events → 10 log lines, covering all Farm / Plot / Seed mappings | Record order, levels, messages and metrics counts all match expectations exactly |
| `TestLogWatcherFiltersLevels` | With `minLevel = ERROR`, delivers 1 DEBUG + 1 ERROR record | Only the ERROR record is kept |

## `TestLogWatcherTranslatesEvents`

### How it is driven

```go
handler := &captureLogHandler{}
metrics := scarecrow.NewMetricsWatcher()
obs := newLogWatcher(handler, metrics, "DEBUG")
if err := obs.Start(); err != nil { t.Fatalf(...) }

for _, event := range events {
    if err := metrics.OnEvent(event); err != nil { t.Fatalf(...) } // 先喂指标
    if err := obs.OnEvent(event); err != nil { t.Fatalf(...) }
}
if err := obs.Stop(); err != nil { t.Fatalf(...) }
records := handler.snapshot()
```

- The minimum level is set to `DEBUG`, otherwise `SeedInputEvent` would be filtered out and the full mapping could not be verified.
- **Each event is fed to `metrics` first and then to `obs`**: the `PlotEndEvent` counts are read from `MetricsWatcher`, and reversing the order would read a stale snapshot. This also mirrors the real ordering in `pkg/assembly`, where "the metrics watcher is registered first".

### Expected records

`events` are, in order: `FarmStart` → `PlotStart` → `SeedInput` → `SeedReplant` → `SeedRipen` → `SeedWither` → `SeedPrune` → `PlotEnd` → `FarmEnd`, producing 10 records in total (the `Structure` of `FarmStart` has only 1 line, contributing 1 extra record):

| # | Level | Message assertion (`strings.Contains`) |
|:-:|------|-------------------------------|
| 0 | `INFO` | `Farm 'farm' start. Structure:` |
| 1 | `INFO` | `a -> b` |
| 2 | `INFO` | `Plot 'a' start with 2 tenders.` |
| 3 | `DEBUG` | `In 'a', Seed 1 input. [1*]` |
| 4 | `WARNING` | `attempt 1 withered: transient. Replanting. [1*]` |
| 5 | `SUCCESS` | `Seed 1 ripened. Fruit is 10. Use 1.00s. [1->2*]` |
| 6 | `ERROR` | `Seed 2 withered: boom. Use 1.00s. [3->4*]` |
| 7 | `INFO` | `Seed 3 pruned. Use 0.00s. [5->6*]` |
| 8 | `INFO` | `Plot 'a' end. Use 2.00s. 1 ripened, 1 withered, 1 pruned.` |
| 9 | `INFO` | `Farm 'farm' end. Use 3.00s.` |

- Assertions use a three-stage approach of "count + per-record level + substring containment": first fail on `len(records) != len(want)`, then compare `Level` and `Message` in order.
- Index 8 also verifies the `MetricsWatcher` integration: `SeedRipen` / `SeedWither` / `SeedPrune` occur once each, so the counts are `1 ripened, 1 withered, 1 pruned`.
- The `[seedID*]` / `[seedID->resultID*]` suffixes of indexes 3~7 correspond to the `SeedID`, `FruitID`, `WeedID` and `PruneID` fields respectively.
- The message of `SeedReplant` contains `attempt 1` and only the `[1*]` suffix (a retry event does not produce a new event ID).

## `TestLogWatcherFiltersLevels`

```go
obs := newLogWatcher(handler, scarecrow.NewMetricsWatcher(), "ERROR")
obs.Start()

obs.OnEvent(scarecrow.SeedInputEvent{Plot: "a", Seed: 1, SeedID: 1, Time: now}) // DEBUG，被丢弃
obs.OnEvent(scarecrow.SeedWitherEvent{Plot: "a", Seed: 1, SeedID: 1, WeedID: 2, Time: now}) // ERROR，保留

obs.Stop()
records := handler.snapshot()
// 断言: len(records) == 1 且 records[0].Level == "ERROR"
```

- `minLevel = levelOrder["ERROR"] = 5`, so both `DEBUG` (1) and `INFO` (3) are filtered out.
- `SeedWitherEvent` leaves `Err` unset, so the message renders as `<nil>`, but this test only asserts the level and the count and does not depend on that text.

## Notes

- **`Stop` is the synchronization point**: `Spout.Stop` closes the channel and waits for the queue to drain (at most 1s) before `snapshot`; not calling `Stop` leaves the record count unstable.
- **`Start` cannot be omitted**: the injected handler's `BeforeStart` is an empty implementation, but the consume goroutine is still started by `Start`.
- **Depends on the metrics delivery order**: if `metrics.OnEvent` were placed after `obs.OnEvent`, the `PlotEnd` counts would be too small and the assertion at index 8 would fail.
- **Only translation and filtering are covered**: directory creation, file opening, appending and closing in `LogRecordHandler` are described by the source code and [`log.md`](./log.md); this test does not touch the filesystem.
- **`FormatTime` is not asserted**: the test uses `time.Now()` as the event time and does not hardcode assertions on the formatting result; to verify the format, use a fixed time and assert the `2006-01-02 15:04:05` shape instead.
